# 考古发掘层位记录系统

用于田野考古发掘中记录 **探方（Grid）→ 层位（Layer）→ 遗物批次（Artifact Batch）** 的 Web 应用。
系统按“覆盖 / 被覆盖”关系维护一张**层位有向无环图（DAG）**，并提供发掘顺序校验、
冲突路径展示、草稿保留、按探方回放层位演变与审计记录导出。

技术栈：**Python 3.11 · Flask · SQLite（零外部服务）· 原生 SVG 渲染（无前端构建）· Gunicorn · Docker / Compose**

---

## 一、核心业务规则

| 规则 | 实现位置 |
| --- | --- |
| 每个探方中层位编号唯一、发掘顺序号唯一（正整数，**先发掘/上层数值小**） | `app/services.py: create_layer` |
| 覆盖关系方向：`覆盖方（upper）→ 被覆盖方（lower）`，且两端必须属于同一探方 | `add_relation` |
| **顺序约束**：`upper.seq < lower.seq`，即覆盖方必须先发掘 | `add_relation` 第一道校验 |
| **无环约束（DAG）**：BFS 检测 `lower → … → upper` 已可达时拒绝（第二道防线） | `app/services.py: _find_path` |
| 发现矛盾时**不写入**关系，原始录入**保留为草稿**并显示**冲突路径** | `drafts` 表 / 冲突草稿页 |
| 遗物只能登记到**当前开放（open）**层位；层位**关闭（closed）后禁止补录** | `register_artifact` |
| **整体调整发掘顺序（预览 → 提交两阶段）**：编号恰好覆盖现存层位、新顺序号为互不重复正整数；覆盖方新顺序号不小于被覆盖方即列出冲突并禁止应用；预览后层位/关系变化则旧提交失效；单事务两阶段更新（先负临时值再落位）杜绝 UNIQUE 中途冲突，原子生效并记录各层位变更前后顺序 | `preview_reorder` / `commit_reorder` |
| 一切成功与被拒绝的写操作都落入 `audit_logs`（成功/失败均留痕） | `app/audit.py` |
| 回放与导出均以审计日志为唯一事实源，逐条重放重建当时图状态 | `app/replay.py` |

> 说明：在“seq 严格沿覆盖方向递增”的不变量下，顺序校验本身即可阻止成环；
> BFS 环检测作为第二道防线保留（例如历史数据顺序号未重排时仍能兜住）。
> 被拒绝的事件保留在回放时间线上，但不改变图状态。

## 二、功能页面

- `/` 探方总览：统计、新建探方、最近操作
- `/grids/<id>` 探方工作台：
  - 层位图 SVG（开放层位绿色 / 已关闭灰色，箭头为覆盖方向）
  - 开放层位、登记覆盖关系、关闭层位
  - **整体调整发掘顺序**：为全部现存层位填写新顺序号后生成预览
  - 遗物批次登记表单（下拉中**只出现开放层位**）
  - 覆盖关系与遗物批次清单
- `/grids/<id>/reorder/<preview_id>?token=…` **顺序调整预览页**：
  新旧顺序对照表、逐条覆盖关系的原/新顺序校验（冲突标红、提交按钮禁用）、
  一键“确认提交（一次性原子生效）”；预览过期（层位或关系在预览后变化）时禁止提交
- `/conflicts` **冲突草稿**：展示冲突路径（如 `L1 → L2 → L3 → L1（成环）`）、
  原始表单、拒绝原因；可“重新校验并提交”或“丢弃”（均留痕）
- `/grids/<id>/replay` **按探方回放层位演变**：逐步前进/后退、跳转，
  每一步显示该时刻的图快照（开放/关闭层位、覆盖边数），冲突事件标红；
  顺序调整事件**旧帧显示旧顺序、该帧及新帧显示新顺序**，被拒绝的调整不改状态
- `/audit` 审计记录：按探方 / 操作类型（含“整体调整顺序”）/ 关键词 / 仅看冲突筛选。
  顺序调整的详情 JSON 含 `changes`（每个层位 `old_seq → new_seq`），可追溯本次变动；
  被拒绝的提交（覆盖冲突 / 预览过期）同样留痕
- `/audit/export` 一键导出当前筛选结果为 **UTF-8 BOM 的 CSV**（Excel 可直接打开）

## 三、一键启动（Docker Compose，推荐）

```bash
docker compose up -d --build
# 打开 http://localhost:8000
```

首次启动会自动建表；由于 Compose 中 `SEED_DEMO=1`，数据库为空时会写入演示数据：

- 探方 **T01**：层位 `L1(顺序1,表土) → L2(顺序2,文化层) → L3(顺序3,生土)`，
  含覆盖关系、遗物批次；L2 已关闭并附带一条“关闭后补录被拒绝”的审计；
  另有一条顺序冲突关系 `L3 → L1` 保留为草稿（可在“冲突草稿”页看到）。
- 探方 **T02**：仅一个开放层位，便于看空白图与回放。

数据持久化在命名卷 `archaeo-data`（容器内 `/data/archaeo.db`）。

停止 / 清除：

```bash
docker compose down          # 停止（保留数据卷）
docker compose down -v       # 停止并删除数据卷（清空所有记录）
```

## 四、本地开发运行（不使用 Docker）

需要 Python 3.11+。

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

export FLASK_APP=app
export DATABASE_PATH="$PWD/archaeo.db"
export SEED_DEMO=1            # 可选：写入演示数据

flask init-db                 # 建表（SEED_DEMO=1 时附带演示数据）
flask run --debug --port 8000
```

生产方式（容器内同此命令）：

```bash
gunicorn --bind 0.0.0.0:8000 --workers 2 "app:create_app()"
```

## 八、使用流程示例（典型田野工作流）

1. 新建探方 `T03`；
2. 按发掘进展依次开放层位 `L1(顺序1) → L2(顺序2) → L3(顺序3)`；
3. 随时登记覆盖关系 `L1→L2`、`L2→L3`（系统即时校验顺序与无环）；
4. 发掘某层期间，把遗物批次登记到该**开放**层位；
5. 该层发掘结束 → **关闭层位**，此后任何人尝试补录都会被拒绝并记入审计；
6. 若误录了反向/成环关系，在“冲突草稿”页查看冲突路径，待修正后重试或丢弃；
7. 田野整理需要重排层位时，在工作台“整体调整发掘顺序”中一次性填写全部现存层位
   （含已关闭层位）的新顺序号 → **先预览**新旧顺序与受影响覆盖关系 → 确认无冲突后
   **凭该次预览提交**；预览后若又增删层位/关系，旧预览被拒绝，须重新预览；
8. 通过“回放”向检查方展示层位演变过程，或在“审计记录”导出 CSV 归档。

## 九、顺序整体调整的事务与并发说明

- **输入校验**：提交的编号必须与本探方现存层位**一一对应**（缺漏/多余都拒绝）；
  新顺序号必须是**互不重复的正整数**（允许非连续，如 `10、20、30`，与开放层位规则一致）。
- **覆盖冲突**：按新顺序评估每条现存关系，凡 `upper.new_seq ≥ lower.new_seq`
  都在预览页逐条列出并标红，提交按钮禁用；冲突预览可以查看但不能应用。
- **防陈旧**：预览保存时记录层位（id/code/seq/status）+ 关系集合的 SHA-256 指纹
  和一次性随机 token（存于 `reorder_previews` 表）。提交时重新比对指纹并重新校验，
  预览后层位或覆盖关系发生任何变化都拒绝并要求重新预览；同一探方只保留最新预览，
  提交成功后预览立即删除，不可重复使用。
- **原子性**：提交在单事务内完成。由于 `UNIQUE(grid_id, seq)` 存在，直接逐条改成
  目标值会在中途撞上唯一约束（如 1、2 对调时第一条就冲突），故采用**两阶段更新**：
  先把全部层位置为互不相同的负临时值（同事务未提交，外部不可见），再统一置为最终值；
  任一步失败（例如触发器 ABORT）整体 `ROLLBACK`，绝不留下部分更新，且失败也留痕。
- **不变量延续**：已关闭层位参与调整，但 `status` / `closed_at` 与遗物批次归属不变；
  调整后新登记的覆盖关系按**最新顺序**校验。审计 `reorder_layers` 详情含全部层位
  `old_seq/new_seq`；回放中旧帧保持旧顺序，调整帧及之后的新帧显示新顺序。
